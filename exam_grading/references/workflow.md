# 全工程の詳細手順（スキャン受領 〜 集約）

作業ディレクトリは SKILL.md「作業フォルダの標準構成」に従う。以下、答案1枚を **sheet**（答案ID）と呼ぶ。

---

## §1. スキャン受領・画像化・表裏ペアリング（P1）

### 1-1. スキャン運用の前提

多くのシートフィーダ型スキャナは片面ずつ一括スキャンするため、
**表面は正順・裏面は逆順**で保存される。

```
1冊 N枚のとき:  表面 p-i  ↔  裏面 p-(N+1−i)     （p-01 始まりの1-indexed）
```

冊が複数に分かれることもある（実例: 1冊目60枚・2冊目72枚の計4PDF）。冊ごとに N が違うので、
冊ごとにペアリング式を持つこと。

### 1-2. 画像化

```bash
pdftoppm -jpeg -r 300 "scan/1_表面.pdf" ".output/採点/pages/1_front/p"
```

- **300dpi**（A4で 2480×3509 px 程度）が実績値。これ以下だと薄い文字が飛ぶ。
- 出力後、**必ず数枚を目視で表裏一致確認する**（1枚目・中間・最終枚）。
- 枚数を数え、答案枚数＋欠席者数＝履修者数 を検算する。

### 1-3. 大問クロップ

`scripts/crop_answers.py` を科目用に改変して使う。要領:

- 座標は 300dpi の絶対ピクセルで定義（`(left, top, right, bottom)`）。
- **大問の境界は少し重ねて切る**（上下に50〜100px の余白を持たせる）。切れると採点不能になる。
- `PIL.ImageOps.autocontrast` を必ずかける（薄い鉛筆が劇的に読みやすくなる）。
- 学籍番号帯（`id`）・裏面の任意記入ID（`backid`）・自由記述欄（`comment`）も別クロップとして切る。
- 座標を決めたら**全答案でズレがないか数枚で確認**する（レイアウトが全員同一なら1組の座標で通る）。

## §2. 本人特定（P2）

1. `crops/<sheet>/id.jpg` をOCRエージェント（1体あたり10枚程度）に並列で読ませる。
   - 名簿（学籍番号・氏名）を**照合辞書として渡す**と精度が上がる。
   - 読み取れない場合は PIL で該当帯をさらに crop → 2倍拡大して再読。
2. 裏面の任意記入ID（`backid`）も読み、表面と突合する（二重チェック）。
3. **名簿と1対1で確定**させる。学籍番号が連番体系なら、**欠番との整合**で誤読を確定できる
   （実績: 4件の誤読をこの方法で確定）。
4. 結果を `sheet_map.json` に保存する。

```json
[{"sheet": "1-01", "sid": "B990001", "name": "見本 太郎"}, ...]
```

**注意点**

- 名簿は**学籍番号入りの公式名簿（成績報告用）を正**とする。LMS のエクスポートには学籍番号がないことがある。
- 留学生は名簿間で姓名の順序が逆になることがある。表記は公式名簿に統一する。
- LMS にいるが公式名簿にいない学生（履修取消等）が存在しうる。欠席の判定は公式名簿基準で行う。

## §5. 集約（P4末）

`scripts/aggregate.py` で、採点JSON・本人特定・自由記述OCR・AI返信を統合して
`採点結果_集約.json`（キー＝学籍番号）を作る。以後の帳票はすべてこれを入力にする。

```json
{
  "990001": {
    "sheet": "2-01", "official_sid": "B990001", "official_name": "見本 太郎",
    "scores": {"1a": [4, "slot0=15,slot1=×,..."], ...},
    "total": 87, "summary": "…1〜2文の講評…", "flags": ["別解: …"],
    "to_teacher": "…", "to_ai": "…", "ai_reply": "…"
  }
}
```

集約時に**採点JSONの氏名と本人特定結果の食い違いを検出**して警告を出すこと（取り違えの最終防波堤）。

## §7. 帳票生成・返却（P6）

| 成果物 | スクリプト | 備考 |
|---|---|---|
| 赤入れ答案（大問ごとの◯△✕＋得点、表面右上に合計） | `annotate_answers.py` | 座標は300dpi基準。全員同一レイアウト前提 |

| 学生コメント返信用Excel | `make_summary.py` | 教員が返信欄に記入 → 成績票にマージ |

→ 返却手順と事故防止は `return_and_appeals.md`。

## §8. 記録の残し方

翌年の自分（と別の担当者）のために、次を必ず残す:

- `.spec/KNOWLEDGE.md` … 科目固有の知見（出題範囲・レイアウト・名簿の癖・クロップ座標の由来）
- `.agent/memory/MEMORY.md` … 作業中に判明した教訓
- `.agent/handoff/HANDOFF.md` … 未完タスク・ブロッカー・締切
- **講義フォルダ直下に「テスト運用申し送り」** … 翌年度に最初に読むべき1枚

**教訓は文書だけでなく、スクリプト本体とテンプレート文面そのものにコメントとして埋め込む。**
実例: 返却事故の教訓を手順書に書いたが、翌回に**別のファイル**（教訓のない旧テンプレート）を使ったため同じ事故が再発した。
文書は読まれないことがあるが、実行するスクリプトは必ず開かれる。
