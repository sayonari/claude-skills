# 採点基準の設計（`採点基準.md` の書き方）

**採点基準は、答案を1枚も採点しないうちに書き切る。** 採点しながら基準を決めると、
先に採点された答案と後の答案で扱いが変わり、不公平が生まれる。また疑義申告に対して説明できなくなる。

雛形: `templates/採点基準_テンプレート.md`

---

## 1. 構成

```
1. 全体方針（表記ゆれ）           ← 全問共通の同一視ルール
2. 大問ごとの正解と部分点の刻み方   ← 数えられる形で
3. 全体方針（末尾）               ← 空欄・判読不能・別解・転記義務・自由記述欄の扱い
```

---

## 2. 全体方針（表記ゆれ）

「中身が合っていれば形式差では減点しない」ものを列挙する。科目に合わせて作る。例（情報系）:

- `lg` / `log` / `log₂` / `log2` は同一視する
- **O / Θ / θ の記号差だけでは減点しない**（増加オーダーが正しければ可）
- 答案は日本語・英語のどちらで書かれていてもよい（バイリンガル講義の場合）
- 区切り記号の違いは不問（`20 30 35` / `20,30,35` / `20→30→35` を同一視）
- 大文字小文字の別（`SUBA` / `suba`）

さらに**AI採点特有の注意**を書く:

- 誤読しやすい字形: 3↔9、3↔5、5↔8、2↔7、1↔7、筆記体の ℓ↔g、i↔t
- 該当する箇所は**必ず拡大確認**してから判定する

---

## 3. 部分点は「数えられる形」で書く

AI に安定して採点させるコツは、**部分点を主観語でなくカウントで定義する**こと。

| 悪い書き方 | 良い書き方 |
|---|---|
| 「おおむね合っていれば部分点」 | 「**誤りマス1個につき −1点（下限0）**」 |
| 「だいたい正しい表なら半分」 | 「**誤りマス数で刻む: 0個=8点／1〜2個=6点／3〜4個=4点／5〜8個=2点／9個以上=0点**」 |
| 「順序がほぼ合っていれば部分点」 | 「完全一致=6点／**隣接2頂点の入替が1箇所のみ**=3点／それ以外=0点。先頭が誤りなら0点」 |
| 「惜しい答えは部分点」 | 「7回=2点。**総プローブ回数の13回と書いた場合は1点**（数え方の解釈違いとして救済）。それ以外0点」 |

**空欄マスの扱いも明記する。**「空スロットに `×` の記入がない場合はそのマスを誤りとする」など。
これを書かないとエージェントごとに判断が割れる。

### 典型誤答を先に決めておく

予想される典型誤答について、部分点を与えるか0点かを**先に**決める。例:

- 「d[B]=7（直行のまま）は典型誤答で0点（部分点なし）」
- 「経路圧縮で経路外の節点まで付け替えた答え（=10）は0点」
- 「部分列の定義を誤り連続部分文字列を答えた場合は0点」

---

## 4. 連鎖切り（前問の誤りを後問に波及させない）

トレース問題では、(a) の表が誤ると (b)(c) も自動的に誤りになる。これをそのまま0点にすると
「1つのミスで大量失点」になり不公平感が強い。**「自分の前問の答えと整合していれば部分点」**を明示する。

```
(b) [2点]: 4。(a)の自分の表の右下値と一致していれば、表が誤っていても1点（連鎖切り）。
(a)(b)は独立採点（どちらも同じ元データから出発するため連鎖しない）。
d[F]=19 は0点。ただし自分の d[D] 値 +6 と整合する d[F] は1点（連鎖切り）。
```

**どの小問が独立採点で、どの小問が連鎖するのか**を全小問について明示すること。

---

## 5. 別解の扱い

- 「模範解答と異なる別解で**数学的に正しい**ものは満点とし、flags に『別解』を記録する」
- **別解の認否は、既存の満点先例との整合で決める**（先例主義）。
  実例: ある学生の別解を認めた前例があったため、同型の申告を即座に満点にできた。
  逆に先例と矛盾する判定をすると、疑義申告への回答が破綻する。
- **「申告文では正しいが、答案にそう書かれていない」ものは認めない。**
  この「答案に書かれた内容で採点する」原則の一貫性が、回答文の説得力になる。
- 別解が多く出そうな問題は、そもそも作問で潰す（→ `exam_design.md`）。

---

## 6. 空欄・判読不能

```
- 空欄は0点。
- 判読不能の場合は無理に推測せず0点とし、flags に「判読困難」を記録する。
  → 判読困難は後で必ず教員確認HTMLに回す（teacher_review.md）。
- 小さく薄い文字を空欄と誤読しないこと。クロップ＋拡大で必ず確認する。
```

**「推測せず0点＋flags」**が重要。AI に推測させると、当たっているように見えて外れる。
0点にした上で教員判断に回すことで、最終的な精度が上がる。

---

## 7. 全体方針（末尾）に必ず入れる項目

- **学生の解答内容を採点JSONに簡潔に転記する**（採点根拠の透明性確保。疑義申告対応で必須）
- 合計点は Python で再計算・検証する
- 採点は「大問クロップ＋autocontrast＋セル拡大」方式で行う
- 「教員に一言」「採点AIに一言」欄は**採点対象外**。ただし内容はOCRして一覧化する
- 図や途中式を描いていても、採点対象は指定された解答（数値・記号）のみ、等の明示

---

## 8. 採点開始後に基準を変えるとき

やむを得ず基準を変える場合は:

1. **全答案に一括で再適用する**（パッチスクリプト `apply_*.py` で機械的に）
2. 変更理由を採点JSONの転記文と flags に残す
3. 変更前後の点数差分一覧を作る（誰が何点変わったか）
4. 影響人数が多い変更は、**教員に「維持か一括適用かの二択」で諮る**

実例: 「講義実装に沿った別解を満点扱いにする」判断で57名が一括 +2点になったケースがある。
個別に認めると不公平になるため、必ず全数に適用する。
