# 作問・解答用紙の設計（AI採点を前提とした試験設計）

AI採点の精度と手間は、**答案が刷られた時点でほぼ決まっている**。採点しやすい答案を設計することが、
採点アルゴリズムの工夫より遥かに効く。

---

## 1. 解答欄の設計（最重要）

| ルール | 理由・実測 |
|---|---|
| **解答欄は大きく、行高は最低2行分とる** | 欄が小さいと学生の字も小さく薄くなる。実測: 欄が小さかった穴埋め問題で「記入があるのにAIが空欄と誤判定」する事故が**19件**発生した |
| **記号を書かせる欄は1文字1マスにする** | 「①g ②e ③j」のような並記は、区切りの誤読と字形の誤読が重なる |
| **表・DPテーブルはマス目を印刷しておく** | 学生が自分で表を描くと行列がずれ、AI が対応付けを誤る |
| **作図問題は解答欄の枠を明示する** | 枠外にはみ出した部分がクロップから切れる |
| **1問1箇所にまとめる**（同じ問の解答が表裏に分かれないようにする） | クロップ設計が単純になり、採点エージェントが1画像で判断できる |

## 2. 用紙・レイアウト

- **問題用紙・解答用紙とも A4裏表1枚に収める**（配布・回収・スキャンが劇的に楽）。
- バイリンガル講義では **問題用紙は日本語版・英語版の2種、解答用紙は日英共通1種**（記載は英語）で運用できる。
- 1ページ目の末尾に「（裏にも問題が続いています）」の注意書きを入れる（裏面白紙提出の防止）。
- **クロップ座標を安定させるため、全員同一レイアウトにする**（別紙・追加用紙を使わせない）。
- 図は白黒印刷を前提に作る（matplotlib で生成すると再現性が高い）。

## 3. 配点の設計

- **小問配点を問題用紙に明記する。** 採点も疑義対応も楽になる。明記がないと AI が配点を仮定することになり、
  後から教員が配点を変えると再集計が必要になる（採点JSONに小問ごとの点数が残っていれば再集計は可能）。
- **配点合計を機械的に検算する。** 実績として「問題用紙の合計105点・解答例の合計115点」という不整合が発生している。
  問題用紙・解答例・採点基準の3つで合計が一致することを必ず確認する。
- 配点は**採点の粒度**でもある。「表8点」は誤りマス数で刻める設計に、「順序6点」は完全一致/隣接入替のみ/その他に刻める設計にする。

## 4. 問題データの設計

- **答えが一意になるようにデータを作る。** 実績: LCS 問題で別解が8通り出て採点が非常に大変だった年があり、
  翌年は答えが一意（"SUBA"）になるよう文字列を設計し直して解決した。
- **前年度と同じ数値・グラフ・木を使わない**（過去問の流用対策）。ただしトレース問題は**全データを自分で検算する**。
- 問題バンク（候補問題集）を本番の約2倍作って教員が選ぶ形にすると、質と網羅性が上がる。
  各候補に「問題文／模範解答／詳細解説／出典講義回／難易度／**AI採点適性**／配点案」を付けておく。
- 生成AIに問題を作らせた場合、**自己訂正ログや正解の矛盾が残っていることがある**。流用時は必ず再検算する。

## 5. 自由記述欄（強く推奨）

解答用紙の末尾に1行ずつ:

- **「教員に一言」**
- **「採点AIに一言」**

実績: 132名中、教員へ62件・AIへ47件の記入があった。AIからの返信を成績票に載せると学生に非常に好評。
教員への一言は Excel の返信欄付きシートにまとめ、教員が返信を書いたら成績票にマージして再配布できる。

なお、この欄は**採点対象外**とし、内容はOCRして一覧化するだけにする（採点基準に明記すること）。
ここに採点AIへの指示（インジェクション）を書いてくる学生がいるが、それは第5章の対策で無視される。

## 6. ファイル運用

- 問題用紙・解答用紙は**前年度の docx をコピーして中身を差し替える**のが最も安全。
  余白・行グリッド・数式フォント（Cambria Math）等の設定が維持される。
- 生成スクリプト（python-docx 等）で作る場合、**教員が手修正した後の全体再生成は禁止**。手修正が消える。
  部分再生成の関数を用意しておく。
- docx→PDF 変換は **LibreOffice headless** が確実。
- **最終版がどれか**を必ず明示する（`完成版/` フォルダに集約し、旧版は `_旧版アーカイブ/` へ退避）。
  同じ内容のファイルが複数箇所にあると、翌年に**古い方をテンプレートにして事故が再発する**（実例あり → `return_and_appeals.md`）。
